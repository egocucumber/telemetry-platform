# ADR-0003: Состояние правил живёт в памяти processor

**Статус:** принято

## Контекст

Правило вида «температура > 85 °C в течение 10 с» имеет состояние: движок
должен помнить, с какого момента условие выполняется и горит ли уже алерт.
Варианты: держать состояние в Redis (общее) или в памяти processor
(локальное).

## Решение

Локальная память, ключ `(rule_id, device_id)`.

Поскольку `telemetry.raw` партиционирован по `device_id`, все измерения
одного устройства в каждый момент читает ровно один экземпляр processor.
Конкурентных писателей в одно состояние нет, поэтому общее хранилище лишь
добавило бы сетевой round-trip на каждое измерение, ничего не дав
консистентности.

## Что происходит при ребалансе или рестарте

Состояние переназначенных устройств у нового владельца начинается пустым.
Эффекты:

* Уже горящее правило объявляется повторно после истечения `For` на новом
  экземпляре. Cooldown в alerter гасит дублирующее уведомление, а в истории
  алертов появляется вторая строка, что приемлемо и видно.
* Условие, державшееся 7 из 10 секунд, начинает отсчёт заново.

Оба эффекта ограничены и самоисцеляются; выигрыш в пропускной способности и
простоте того стоит. Если когда-нибудь понадобится более строгая гарантия,
состояние можно сбрасывать в Redis по `OnPartitionsRevoked`, не меняя
интерфейс движка.

## Перезагрузка правил

Правила кешируются в движке и обновляются по сообщению Redis pub/sub
(`rules.changed`, публикует query API) с периодическим запасным опросом.
Перезагрузка атомарно заменяет набор правил и удаляет состояние исчезнувших,
чтобы удалённое правило не могло держать алерт вечно.
